# EventSpace

_Система управления мероприятиями / платформа для создания и регистрации на события_

EventSpace — это веб-приложение для организации мероприятий. Проект разрабатывается в рамках учебного курса по ИТ и веб-программированию в БГУИР.

## Технологии

- **Backend**: Node.js + Express
- **Шаблонизатор**: EJS (генерация HTML на сервере)
- **База данных**: SQLite (better-sqlite3) — используется только для логирования событий (запросов)
- **Frontend**: HTML / CSS (шаблоны EJS + `public/css`)
- **Дополнительно**:
  - nodemon — авто-перезапуск сервера в разработке
  - Prettier — форматирование кода

## Запуск

```bash
npm install
npm start        # или npm run dev (с nodemon)
```

Приложение откроется на http://localhost:3000

## Структура проекта

```
server.js              — Express-приложение, настройка EJS и маршруты
db.js                  — база данных SQLite, таблица logs
data/events.js         — данные о мероприятиях (массив в памяти)
middleware/
  logger.js            — логирование метода, URL и времени запроса (консоль + БД)
  auth.js              — имитация авторизации (?auth=1)
  errors.js            — обработка ошибок 404 и 500
views/
  partials/            — общие части страниц (header, footer, event-card)
  index.ejs            — список мероприятий
  item.ejs             — детальная страница мероприятия
  add.ejs              — форма добавления
  login.ejs            — имитация входа
  logs.ejs             — журнал событий из базы данных
  404.ejs, 500.ejs     — страницы ошибок
public/                — статические файлы (css, images)
```

## Маршруты

| Метод | Адрес       | Описание                                        |
| ----- | ----------- | ----------------------------------------------- |
| GET   | `/`         | список мероприятий                              |
| GET   | `/item/:id` | детальная страница мероприятия                  |
| GET   | `/add`      | форма добавления (только для авторизованных)     |
| POST  | `/add`      | добавление мероприятия в массив                 |
| GET   | `/login`    | страница имитации входа                         |
| GET   | `/logs`     | журнал событий из БД (только для авторизованных) |

## Авторизация (имитация)

Middleware проверяет query-параметр `?auth=1`:

- есть параметр → `req.user = { name: 'Пользователь' }`;
- нет параметра → `req.user = { name: 'Гость' }`, а при попытке открыть `/add` или `/logs` происходит редирект на `/login`.
